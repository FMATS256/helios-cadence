# Architecture decisions
- The client account portal resolves ownership from administrator-linked profiles, uses authenticated RLS reads and atomic pending payment submissions, and never exposes the staff shell or permits client approval; profile ownership changes are protected by a database trigger.
- Website account opening uses the existing IMT HMAC connection and a service-only atomic database function with durable application IDs; manager selection and contact creation commit together, so retries cannot duplicate accounts or leave partial onboarding.
- Email and original account-opening API addresses share one server handler; a customer-insert trigger saves the assigned manager's in-app alert atomically for every creation path without duplicate alerts on application replays.
- Staff creation, lead conversion and website opening await one shared welcome sender with an atomic customer claim; the existing IMT inbox transport persists personalized signed messages before sending, and failed/ambiguous attempts are never blindly resent.
- Quotation previews and PDF downloads share a saved-value document model; pure PDF generation renders the branded layout without changing external-engine lifecycle or financial calculations.

- Direct Finance payment recording must require a destination cash account and post both its cash movement and balanced journal entry, so recorded receipts always update account and ledger balances.
- Inbox outbound mail uses only the IMT website gateway and saves its message and quotation snapshot before delivery, so persistence failures cannot cause an unrecorded send or a direct-provider fallback.
- Base44 webhook resolves client ownership from the protected system setting, not incoming customer identifiers, so requester data cannot route tickets to another client.
- Email HTML renders in a sanitized, script-disabled sandbox; attachments require visible message ownership and use retained storage or gateway-supplied HTTPS links, never another mail provider. Prepare attachment blobs before download clicks so phone sharing and downloads retain user activation; preview only safe image, PDF and text formats.
- Department senders are authorized from protected staff roles; personal drafts and organization are atomically persisted under owner-only policies, while internal notes inherit enquiry visibility.
- Default inbox and transactional signatures share one email-safe table template and staff-title resolver; compact inline mobile typography disables text autosizing, with desktop media overrides and a single linked promotional image to preserve proportions across mail clients. Custom personal signatures remain explicit overrides.
- Inbox conversation rendering uses a dedicated collapsible message view with the latest message expanded first, authorized thread prefetching and foreground refresh, so older HTML signatures do not delay access to new replies.
- Compose restoration and outbound conversation display remove identifiable staff signature blocks without changing stored messages; delivery appends signatures separately so clients still receive them.
 - Reply composers show the latest inbound HTML in a separate sanitized read-only preview, never inside the editable or outgoing body, so client branding is visible without being sent back.
